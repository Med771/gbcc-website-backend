# Сверка ТЗ (CRM) с текущим backend

**Договорённость:** этот репозиторий — **сайт GBCC + модуль CRM** под префиксом `/crm/**`. Менеджер в ТЗ = роль **ADMIN**, руководитель = **OWNER**. Статусы и координаты вводятся вручную; **внешние интеграции** (телефония, геокодеры, push) **не используются** — «напоминания» реализуются через **API** (списки задач, `GET /crm/tasks/overdue`, фильтры по сроку).

Условные обозначения:

| Символ | Смысл |
|--------|--------|
| ✅ | Реализовано в этом backend (API + схема БД) |
| 🔶 | Частично / упрощённо относительно формулировок ТЗ |
| ➖ | Вне backend (только UI / процесс) |

Источник требований: `Техническое задание (ТЗ).pdf`.

---

## 1. Модуль организаций (ТЗ §3)

| Требование ТЗ | Статус | Реализация |
|---------------|--------|------------|
| Карточка организации, адреса, этаж, комментарии, виды продукции, объёмы, график, срок сотрудничества, статус клиента | ✅ | `crm_organization`, API `/crm/organizations` |
| Несколько контактов | ✅ | `crm_organization_contact`, CRUD под `/crm/organizations/{id}/contacts` |
| История изменений контактов | ✅ | `crm_organization_contact_history` (снимки при PATCH контакта) |
| Редактирование полей | ✅ | PUT организации, PUT контакта |

---

## 2. Модуль поставок (ТЗ §4)

| Требование ТЗ | Статус | Реализация |
|---------------|--------|------------|
| Поставка: организация, дата, продукция, количество, статус, комментарий | ✅ | `crm_supply`, `/crm/supplies` |
| Долгосрочные контракты, график, частичные поставки | 🔶 | `crm_contract`, `crm_contract_line` (ручные статусы строк); связь факта поставки со строкой — опционально `contractLineId` |

**Граница с витриной:** заказы интернет-магазина остаются в **`/order`** (B2C); B2B-поставки CRM — только **`/crm/supplies`**.

---

## 3. Холодные звонки / лиды (ТЗ §5)

| Требование ТЗ | Статус | Реализация |
|---------------|--------|------------|
| База потенциальных клиентов | ✅ | `crm_lead`, `/crm/leads` |
| Статус, отдел, комментарий менеджера | ✅ | Поля лида + `CrmLeadStatus` |
| Назначение на менеджера | ✅ | `assigned_to_account_id`; переназначение OWNER — `PATCH /crm/leads/{id}/assign` |
| Конвертация в организацию | ✅ | `POST /crm/leads/{id}/convert` |
| История взаимодействий (дата, менеджер, результат, следующий шаг) | ✅ | `crm_interaction`, `/crm/interactions` (привязка к организации **или** лиду) |

---

## 4. Задачи и напоминания (ТЗ §6)

| Требование ТЗ | Статус | Реализация |
|---------------|--------|------------|
| Перезвон: дата/время, причина, комментарий | 🔶 | `crm_task.due_at` (Instant), `reason`, `comment`; отдельное поле «только время суток» не вынесено |
| Список ближайших / просроченных | ✅ | Поиск `/crm/tasks` с фильтрами `dueBefore` / `dueAfter`, `GET /crm/tasks/overdue` |
| Фильтры по менеджеру, дате, статусу, организации | 🔶 | Фильтры по `assigneeId`, статусу, `organizationId` / `leadId`; «по менеджеру» для ADMIN = только свои задачи через скоуп |

Push/e-mail уведомлений **нет** (по договорённости).

## 5. Карта (ТЗ §7)

| Требование ТЗ | Статус | Реализация |
|---------------|--------|------------|
| Точки организаций и поставок | ✅ | Ручные `latitude`/`longitude` на организации; `deliveryLatitude`/`deliveryLongitude` на поставке; `GET /crm/map/pins` |
| Объекты компании | ✅ | `crm_company_object`, CRUD под `/crm/map/company-objects` |

## 6. Роли (ТЗ §9)

| Требование ТЗ | Статус | Реализация |
|---------------|--------|------------|
| Администратор полный доступ | 🔶 | **OWNER** — полный доступ к CRM; **ADMIN** — скоуп по назначению / assignee задач |
| Менеджер — только свои клиенты/задачи | ✅ | Паттерн: ADMIN + `assigned_to` на org/lead + assignee на task |
| Руководитель — вся база и статистика | 🔶 | OWNER видит всё; сводка **`GET /crm/metrics/summary`** (агрегаты в рамках скоупа) |

## 8. Связь с сайтом

В карточке организации — опциональные FK на `contact_request` и `cooperation_request` (поля при создании организации). Автосоздание лида при `take` заявки **не** подключено (можно добавить отдельной задачей).
