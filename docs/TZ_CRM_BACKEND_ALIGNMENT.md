# Сверка ТЗ (CRM) с текущим backend

**Договорённость:** этот репозиторий — **сайт GBCC + модуль CRM** под префиксом `/crm/**`. Менеджер в ТЗ = роль **ADMIN**, руководитель = **OWNER**. Статусы и координаты вводятся вручную; **внешние интеграции** (телефония, геокодеры, push) **не используются** — «напоминания» реализуются через **API** (списки задач, `GET /crm/tasks/overdue`, фильтры по сроку).

Условные обозначения:

| Символ | Смысл |
|--------|--------|
| ✅ | Реализовано в этом backend (API + схема БД) |
| 🔶 | Частично / упрощённо относительно формулировок ТЗ |
| ➖ | Вне backend (только UI / процесс) |

Источник требований: `Техническое задание (ТЗ).pdf`.

## 8. Связь с сайтом

В карточке организации — опциональные FK на `contact_request` и `cooperation_request` (поля при создании организации). Автосоздание лида при `take` заявки **не** подключено (можно добавить отдельной задачей).

Аккаунт покупателя (**`account`**) может быть связан с CRM: **`crm_organization_id`**, **`brought_by_manager_id`** (менеджер-привлечелец). Заказ витрины — опционально **`crm_organization_id`**. Ручная и вычисляемая аналитика клиента — **`customer_analytics`**, API **`GET/PUT /account/customer/{id}/analytics`**.
